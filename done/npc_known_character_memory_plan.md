# План: долговременная память для именных персонажей (Summary + Recent)

Цель — настоящая **межсессионная** память для известных персонажей (Michael, Franklin, Trevor, Lester, Lamar, Amanda и т.д. из таблицы `KnownCharacters`): они помнят прошлые разговоры и встречи, и память **не обнуляется** между сессиями и не «забывается» со временем.

## Почему для именных это работает (а для толпы — нет)

LLM **не помнит сам** — он видит только то, что мы кладём в промпт. Память = то, что подаём в запрос. Для случайного прохожего после рестарта нет способа понять «тот же это пед». А у именного есть **стабильный уникальный ключ — имя модели** (`player_zero`, `ig_lestercrest`…), и в мире обычно ровно один экземпляр. Значит ключ памяти = модель, и при любой встрече (сейчас / после выгрузки / после перезапуска) подтягиваем ту же память. Persistence-флаги и respawn не нужны.

> Это заменяет `npc_persistent_memory_plan.md` для **именных** персонажей. Толпа остаётся на памяти в пределах сессии + чистка.

## Подход B: Summary + Recent

Модель не помнит — поэтому храним и шлём в промпт две вещи на персонажа:
- **Summary** — сжатый «дневник отношений»: кто игрок этому персонажу, что между ними было, ключевые факты/обещания/события.
- **Recent** — последние ~12 реплик дословно.

В промпт кладём **Summary + Recent** — объём маленький и предсказуемый, но покрывает всю историю по смыслу. Так персонаж помнит суть сколь угодно долго при крошечном запросе.

**Сворачивание:** когда Recent превышает порог (~20 реплик), одним дешёвым доп-вызовом LLM обновляем Summary («обнови сводку памяти этими новыми событиями: …») и подрезаем Recent до последних ~12. Память не дословная, а по смыслу — именно то, что нужно для «помнит, что было».

## Зафиксированные решения
- Глубина: **подход B** (Summary + Recent), не просто окно.
- Ключ памяти: **имя модели** персонажа.
- Сохранение: **после каждого обмена** (файл крошечный).
- Recent ≈ **12** реплик; порог сворачивания ≈ **20**.
- Только для именных (`IsKnownCharacter`); толпа — без изменений.

## Модель данных (`scripts/npc_memory.json`)

```
{
  "player_zero":   { "summary": "…что игрок и Майкл пережили вместе…", "recent": ["Player: …", "Michael De Santa: …"] },
  "ig_lestercrest":{ "summary": "…", "recent": [ … ] }
}
```

## Шаги реализации

1. **`NpcMemoryStore`** (по образцу `VehicleFavoritesStore`, `System.Text.Json`): load/save `npc_memory.json`; путь добавить в `ScriptPaths`. API: `Get(modelName) -> (summary, recent)`, `Save(modelName, summary, recent)`.
2. **`NpcIdentity`**: добавить `Summary` (string) и `ModelKey` (имя модели); `Recent` = существующий `ChatHistory`. Поднять/убрать жёсткий лимит 10 в пользу Recent≈12.
3. **`NpcManager.TryCreateKnownCharacterIdentity`**: при создании личности известного персонажа — подгрузить `summary`+`recent` из стора по `kc.Model`, проставить `ModelKey`.
4. **`AiApiService`**: в системный промпт для именных добавить блок «MEMORY (what you remember about this player): {summary}», а историю слать как Recent. Добавить метод `SummarizeAsync(oldSummary, foldedLines)` — дешёвый вызов (gpt-4o-mini) для обновления Summary.
5. **`AiController.ProcessInteractionAsync`** (или менеджер): после обмена — для именного дописать реплики в Recent, при превышении порога вызвать сворачивание в Summary, затем `NpcMemoryStore.Save`. Сохранять только для `IsKnownCharacter`.

## Стоимость / нюансы
- gpt-4o-mini дешёвый: Summary — абзац, Recent — пара строк → запрос лёгкий и стабильный по размеру.
- +1 дешёвый вызов на сворачивание (нечасто, по порогу).
- Память по смыслу, не дословная — это и есть цель «помнит, что было».
- Сворачивание — async, не блокирует игру (как и остальной пайплайн), с тем же `CancellationToken`.
